# Specification: Post-upgrade drift investigation (mixed-era, retention ordering, BLE precision)

## Problem Statement

Firmware 1.8.0 shipped on 2026-04-01 and kept `SHOT_LOG_VERSION=5` while changing BLE wire-format precision, retention policy (`MAX_HISTORY_ENTRIES=100` → `MIN_FREE_SPACE_BYTES=500 KB`), and the companion-sidecar eviction rule. The parser has no version gating — same version byte in + same parser out, regardless of whether internal semantics shifted. This spike determines three behavioral invariants — mixed-era `.slog` compatibility, shot-history retention ordering + purge-order, and BLE-precision round-trip float drift — so that ticket 016's fixtures and every cross-era historical comparison the agent does can be trusted or explicitly version-gated. Silent drift on any of the three corrupts `/feedback` trend analysis and `/diagnose` historical comparisons; the blast radius justifies the check even when the most likely outcome is `unable to test` (pre-upgrade fixtures are confirmed unavailable per research). Output is three dated sections appended to `research/gaggimate-1-8-0-upgrade/verification-notes.md`, each concluding with a **three-valued verdict**: `drift detected` | `no drift` | `unable to test`. No fourth "soft fallback" verdict is permitted — partial or incomplete structural proof maps to `unable to test`, not to a hybrid state.

3. **Sub-question (c) — BLE-precision round-trip drift section** — same structural requirements as (1).

     - (i) Exhibit the Python parser's decode surface. The cardinality is derived from the grep, not picked by the author.

Classes must include: sensor-sample write path, BT-scale BLE deserialization path (weight samples `v`/`vf`), profile-target BLE/WS path (`tp`/`tt`/`tf` values and phase-transition target fields), and any additional classes surfaced by the grep in (ii).
   - If any enumerated path cannot be fully traced from source (e.g., BT-scale BLE path is gated by a vendor-specific firmware module), the verdict is `unable to test`, not a partial-coverage state. No "residual risk" verdict wording is permitted.

## Non-Requirements

- **No code changes.** The spike does not modify `mcp/src/`, `parsers/`, `transformers/`, or any shipped Python. Ad-hoc analysis scripts stay in the lifecycle scratch directory and are not committed.
- **No fixture recapture.** No `.slog` is added to `mcp/tests/fixtures/shots/` or `{private_repo}/mcp-data/shot-archive/` as part of this spike.
- **No parser version-gating implementation.** If drift is detected, the follow-up ticket owns remediation; 021 does not edit parser/transformer version logic.
- **No retroactive edits to closed verification-notes.md entries.** The 2026-04-18 manage_shot_notes entry is not edited to add SHA pins; the convention applies only to new entries going forward.
- **No statistical-methodology infrastructure.** Per-field delta aggregation tooling (if needed for a pre/post empirical comparison) stays ephemeral in the scratch dir; no committed utility.
- **No upgrade-documentation / upgrade-skill implementation.** The spike *recommends* a lightweight progressive-disclosure upgrade surface in verification-notes.md advisory prose; building it is a separate user-initiated follow-up at the project owner's discretion, not a spike-spawned obligation.
- **No CLAUDE.md edits.** Any new semantic traps discovered by the audit are recorded in the verification-notes.md section itself. Updating CLAUDE.md is a user-initiated follow-up at their discretion, not spike-spawned.
- **No eviction simulation.** Per 021's AC, purge-order is observed passively during the investigation window; no artificial space pressure is induced.
- **No "soft fallback" or "partial coverage" verdict state.** Sub-question (c) cannot close with a "residual risk" or "covered-in-part" verdict — incomplete proof maps to `unable to test`.

## Edge Cases

- **Pre-upgrade fixture surfaces unexpectedly** (user discovers a pre-2026-04-01 `.slog` on device, in Time Machine, in iCloud backup, or via `git log --all`): sub-question (a) and/or (c) verdict shifts from `unable to test` → pairwise comparison with N=1 caveats. Statistical methodology defaults to **mean delta + max |delta| per field** across aligned samples. Single-fixture diff still contributes a stronger signal than source-only when available, but the `**Verdict**:` line still uses only the three-valued vocabulary. This edge case is **low-probability** per research findings (shot archive confirmed to contain only 246/247/249, shot 170 evicted) but is retained because the `git log --all -- mcp-data/shot-archive/` audit in Req 4.5 has a nonzero chance of surfacing a historically-added-and-removed `.slog`.
- **No eviction observed during the investigation window**: sub-question (b) section includes on-wire ordering observation + source-proven purge rule + "no eviction observed during this window" note. Verdict is `no drift` (the retention invariant is source-proven; live signal corroborates). Legitimate per 021's AC.
- **Orphan index entries found**: entries whose `.slog` 404s are flagged in the (b) section with IDs + timestamps. If any timestamp precedes 2026-04-01, that is evidence of a pre-upgrade shot that *did* cross the boundary but is now inaccessible — noted as methodology caveat, not a drift signal in itself.
- **Partial drift detection** (e.g., only `v`/`vf` drifts, other fields stable): section verdict is `drift detected` with the affected field set enumerated in the evidence. Follow-up ticket (spawned per 021's AC) inherits the narrowed scope.
- **Source-proof path is incomplete for (c)**: verdict is `unable to test`, not a partial-coverage state. The section's evidence enumerates which paths were traced and which are not traceable from public source. Req 7's `Status: deferred-uninvestigated.` marker applies.
- **Firmware tag re-pointed mid-spike**: SHA-pinned citations (Req 6) prevent evidence rot. If the spike agent observes a tag move during evidence gathering, the section cites both the old SHA and the current tag SHA with the date of observation, and notes the move in prose.
- **Agent evidence hallucination** (web-research agent fabricates line numbers or filesystem claims): mitigated by independent `WebFetch` re-fetch of every cited blob URL at the tag SHA, with the resulting line quoted inline. For non-blob evidence (command output for 4.5, diff output for 4.3), mitigation is embedding the full output rather than a summary — the artifact itself is the check.

## Technical Constraints

- **Parser + transformer entry points** (source of truth for (a) and (c) analysis):
  - `mcp/src/gaggimate_mcp/parsers/shot.py` → `parse_binary_shot(data, shot_id)`.
  - `mcp/src/gaggimate_mcp/transformers/shot.py` → `transform_shot_for_ai(shot)`.
  - `mcp/src/gaggimate_mcp/parsers/index.py` → `parse_binary_index(data)` preserves on-wire order.
  - `mcp/src/gaggimate_mcp/api/http.py` → `GaggimateHTTPClient.fetch_shot()` and `fetch_shot_index()` for live device I/O.
- **Raw-parser field scales** (structural quantization floor): `TEMP_SCALE=10`, `PRESSURE_SCALE=10`, `FLOW_SCALE=100`, `WEIGHT_SCALE=10`, `RESISTANCE_SCALE=100`. Any systematic drift below `1/scale` is structurally impossible and does not constitute drift signal.
- **Verification-notes template** (from 2026-04-18 / 2026-04-19): `## YYYY-MM-DD — <subject>` → `**Method**:` → numbered steps or labeled categories → fenced raw-data blocks → `**Verdict**:` → `Status:` marker → horizontal rule.
- **Shot-id padding**: 6-digit zero-padded for device URLs and parser invocation; unpadded for WS `notes` endpoint. Relevant only if the spike fetches a candidate shot (unlikely given fixture unavailability).
- **Auto-commit policy scope**: the private-repo auto-commit policy (CLAUDE.md Data Architecture) does NOT fire for writes to `research/gaggimate-1-8-0-upgrade/verification-notes.md` — that file lives in the main repo. Normal `/commit` flow applies. Req 5's read-only invariant on the private repo prevents any accidental private-repo write.
- **Exact-equality contract on goldens** (ticket 016): transformer pre-rounds at 1 dp / 2 dp. Any drift below the rounding threshold does not surface in transformed output. Sub-question (c) must diff **raw parser output**, not transformed output, to see ULP-level drift.
- **Walker (`shot_fixture_walker.compare`) is reusable for (a)** with `max_mismatches` raised; exact-equality semantics correct for transformed-output diffs. **Not suitable for (c)** which needs per-field statistical aggregation across aligned samples.
- **Upstream firmware** at `https://github.com/jniebuhr/gaggimate`, tags `v1.7.3` and `v1.8.0` (released 2026-04-01). SHA-pinned citations required in Req 6.
- **Filesystem**: SPIFFS or SD_MMC (chosen via `controller->isSDCard()`), not LittleFS. Correct filesystem-framing matters for the (b) source analysis.
- **Evidence floor** (per user approval at spec time): source-only verdicts acceptable for structural claims when Req 3's enumeration is exhaustive (proven via the grep in Req 3(ii)) and every class is fully traced. For (b), a live signal is required — source-only is not acceptable even when source is complete. For (a), empirical pre/post diff is preferred when any pre-upgrade fixture surfaces; source-only fallback is acceptable only if Req 4.1 + 4.2's byte enumerations confirm zero cross-tag divergence in the full `.slog` binary shape.
- **Double-counting prohibition**: Req 3(i)'s parser decode-surface exhibit and Req 4.1's phase-transition byte enumeration and Req 4.2's header-region byte enumeration produce distinct artifacts. The same byte-offset table cannot discharge multiple requirements — each requirement's evidence must be independently labeled in the section.
