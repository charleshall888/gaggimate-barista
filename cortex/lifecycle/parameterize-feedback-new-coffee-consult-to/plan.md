# Plan: parameterize-feedback-new-coffee-consult-to

## Overview
Make `feedback`, `consult`, and `new-coffee` resolve the active grinder from the `user-setup.md` Grinder field instead of hardcoding the Baratza Sette 270. A single source-of-truth clause in `CLAUDE.md` (the "Active Grinder field parsing contract") defines two explicit keyword→file maps (a quick-tier map and a deep-tier map — full filenames, never string-interpolated) with case-insensitive substring matching, first-match-in-map-order resolution, and an attempt-Read-then-fallback degrade path, mirroring the existing Puck Screen field parsing contract. Each skill restates the operative read inline via one canonical sentence (defined in Task 2) and points at the resolved `knowledge/grinders/` reference; no skill names any grinder as a default.

> **Critical-review fixes folded in (cycle 1):** the deep tier is now an explicit map, not a `<GRINDER>_REFERENCE.md` template (A1); existence pre-checks are reframed as attempt-then-fallback (tension); Task 8's sweep catches the `10M`/`11A` token family and gains Task 2 in its join (A2/A3); a canonical inline-restatement sentence is shared across the three skills (B); `_`-prefixed siblings are mechanically excluded and the open-keyword collision rule is pinned (B).

  1. **Read** the Grinder row from `user-setup.md`.
  2. **Quick-tier map** (explicit full filenames, NOT interpolated): `sette` → `knowledge/grinders/SETTE_270.md`; `df64v` → `knowledge/grinders/DF64V.md`. Matched by plain case-insensitive substring of the Grinder value.

The nudge may NAME `_TEMPLATE.md` as advice text; it must never load `_TEMPLATE.md` as content. This fallback covers ALL of: (a) Grinder row missing/blank/whitespace/`None` (case-insensitive); (b) field matches no keyword; (c) mapped file Read fails; (d) `user-setup.md` unreadable (missing / unconfigured template / dangling symlink).
  6. **Guardrails**: do not invent grinder categories beyond mapped rows; do not hardcode any single grinder as a default. Adding a grinder is one quick-map row + the reference file (optionally one deep-map row) — one-edit, not zero-edit.
  7. **Canonical inline-restatement sentence** (fixes the divergence B-finding): the clause includes one verbatim sentence that the grinder-aware skills copy inline (Tasks 3, 4, 5 mirror it word-for-word, the way `feedback` and `diagnose` share the Puck Screen sentence): *"Per the CLAUDE.md Active Grinder field parsing contract, read the `user-setup.md` Grinder field, resolve the active grinder reference by case-insensitive substring against the contract's map (first match wins), attempt to load that `knowledge/grinders/` file, and on any miss or unreadable `user-setup.md` degrade to grinder-relative step advice plus the unconfigured nudge — never error."*
  8. **SSOT reconciliation** (fixes the second-source B-finding): the contract clause is the authoritative resolver; add a one-line pointer from the "Knowledge Files" list at `CLAUDE.md:29-30` to the contract (e.g. "grinder selection is governed by the Active Grinder field parsing contract below") so the descriptive list cannot silently diverge from the map. Do not remove the existing two grinder lines.
