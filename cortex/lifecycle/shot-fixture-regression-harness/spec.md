# Specification: Shot-fixture regression harness

## Problem Statement

The MCP shot-analysis pipeline (`mcp/src/gaggimate_mcp/parsers/shot.py` + `mcp/src/gaggimate_mcp/transformers/shot.py`) is about to be modified by three 1.8.0 upgrade tickets: 015 adds weight-flow fields to the transformer, 018 ports the DDSA phase-exit-reason algorithm, and 021 investigates BLE float-precision drift. Today there are no regression fixtures — every change is validated by hand against whatever shot is fresh in history, and silent drift in historical-shot diagnosis would go unnoticed. This harness checks in a small set of representative `.slog` fixtures + golden transformer output + a pytest that asserts deep equality, so future transformer changes are validated against known-good output at review time.

> Epic reference: `research/gaggimate-1-8-0-upgrade/research.md` — Feasibility Assessment and Decomposition Candidates P1 item 3.

## Requirements

1. **Fixture directory and binaries**: `mcp/tests/fixtures/shots/` contains at least three `.slog` files checked into the main repo.
   - *Acceptance*: `ls mcp/tests/fixtures/shots/*.slog | wc -l` returns ≥ 3 on main branch post-merge.

2. **Golden JSON outputs (full surface)**: Alongside each `.slog`, a `<shot_id>.golden.json` containing the **complete** `TransformedShot` output — every field of `TransformedSample[]`, `ShotSummary`, per-phase aggregates, `ComplianceMetrics`, and any derived values — produced by running the current parser + transformer on that `.slog`.
   - *Acceptance*: for every `.slog` in the fixture directory, a sibling `<shot_id>.golden.json` exists (`python -c "import pathlib; p=pathlib.Path('mcp/tests/fixtures/shots'); print(all((p/(s.stem+'.golden.json')).exists() for s in p.glob('*.slog')))"` prints `True`).

3. **Golden byte-stability across contributors**: Golden JSON files are written with `json.dumps(transformed, sort_keys=True, indent=2)` followed by a trailing newline, UTF-8 encoding. This requirement guards against cross-environment serializer drift (Python minor-version differences, locale, OS) — not single-invocation correctness, which is already guaranteed by the transformer's pre-rounding + `sort_keys=True`.
   - *Acceptance*: regenerating goldens twice back-to-back on the same committed `.slog` via the goldens-only refresh path (Requirement 6) produces byte-identical files (`python -m gaggimate_mcp.tools.refresh_fixtures <id>; cp mcp/tests/fixtures/shots/<id>.golden.json /tmp/a.json; python -m gaggimate_mcp.tools.refresh_fixtures <id>; diff /tmp/a.json mcp/tests/fixtures/shots/<id>.golden.json` exits 0). The same check must also pass when run via the `--fetch` capture path provided device connectivity is stable.

4. **Regression pytest file**: `mcp/tests/test_shot_regression.py` parametrizes over every `.slog` file in `mcp/tests/fixtures/shots/`, runs `parse_binary_shot` then `transform_shot_for_ai`, loads the sibling golden JSON, and asserts deep equality using **exact equality on every field** (strings, integers, booleans, `None`/null, floats, list lengths, dict keys). No float tolerance is applied — the transformer pre-rounds all numeric output fields (see Technical Constraints), making exact equality both achievable and load-bearing. If a future transformer change introduces un-rounded floats, this test will fail by design, forcing a discussion before such floats enter the contract.
   - *Acceptance*: `pytest mcp/tests/test_shot_regression.py` exits 0 on a clean checkout with the committed fixtures and goldens.

5. **Custom deep-equality helper with field-path failure messages**: The pytest uses a project-local, stdlib-only deep-equality walker that on mismatch raises `AssertionError` whose message names the full field path + expected + actual. Example message: `phases[1].samples[12].weight_flow_g_s: expected 2.14, got 2.09`. The walker must correctly handle: list-index path tracking (`[N]` notation), `isinstance(x, bool)` before numeric checks (Python's `True == 1` trap), distinct messages for type mismatch / extra key in actual / missing key in actual, and continue-through-mismatches (collect up to N=10 differences before raising) to give useful failure output when a refactor produces wholesale drift. The walker itself has pytest unit tests in `mcp/tests/test_shot_fixture_walker.py` covering each of these cases.
   - *Acceptance*: running `pytest mcp/tests/test_shot_fixture_walker.py` exits 0; and introducing an artificial drift in the transformer (e.g., adding `+ 0.01` to one rounded summary field) and running the regression test produces a failure message containing the field path of the drifted field, verifiable by reading the pytest output.

6. **Refresh CLI with two modes**: A Python module at `mcp/src/gaggimate_mcp/tools/refresh_fixtures.py` implements the refresh workflows.
   - **Default mode** (no flag): `python -m gaggimate_mcp.tools.refresh_fixtures <shot_id>` regenerates `<shot_id>.golden.json` from the **committed** `mcp/tests/fixtures/shots/<shot_id>.slog` bytes. No device connectivity needed. This is the workflow downstream tickets (015 transformer changes) will use — run the new transformer against existing fixture bytes, review the diff.
   - **Fetch mode** (`--fetch`): `python -m gaggimate_mcp.tools.refresh_fixtures <shot_id> --fetch` fetches `.slog` bytes from the device via the existing `mcp/src/gaggimate_mcp/api/http.py` path, overwrites the committed `.slog` file, and regenerates the golden. This is the initial-capture workflow used during 016 implementation and anytime a fixture needs re-capture.
   - Both modes write goldens per Requirement 3 (byte-stability rules). Default mode errors clearly if the committed `.slog` is absent (points the user to `--fetch`). Fetch mode errors clearly on device 404 (shot_id not on device) or connection failure.
   - *Acceptance*:
     (a) default mode with a committed `.slog`: `python -m gaggimate_mcp.tools.refresh_fixtures <committed_id>` exits 0 and produces a byte-stable golden (paired with R3);
     (b) default mode with no committed `.slog`: `python -m gaggimate_mcp.tools.refresh_fixtures missing_id_xyz` exits non-zero with a message instructing the user to use `--fetch`;
     (c) fetch mode with device connectivity: `python -m gaggimate_mcp.tools.refresh_fixtures <valid_device_id> --fetch` exits 0 and produces both files;
     (d) fetch mode with invalid ID: `python -m gaggimate_mcp.tools.refresh_fixtures invalid_id_9999999 --fetch` exits non-zero with a clear error.

7. **Fixtures README**: `mcp/tests/fixtures/shots/README.md` documents for each fixture: origin `shot_id`, profile name, coffee (if known from session memory or user-setup), the archetype slot intended (bloom-slide / decline / BT-artifact / diverse alternate), the rationale, and any substitution note if the fixture differs from the ticket's named candidates. Also documents: (a) test invocation `pytest mcp/tests/test_shot_regression.py`, (b) both refresh workflows from Requirement 6 — default (existing `.slog` → new golden, use this for transformer changes) vs `--fetch` (re-capture from device, use this to add new fixtures), (c) the exact-equality contract from Requirement 4 including the load-bearing pre-rounding invariant, (d) the byte-stability convention from Requirement 3 so future refactors don't silently break it, (e) a short note that contributors refreshing goldens should use a Python minor version consistent with the existing goldens (e.g., 3.13.x) to avoid cross-version `repr(float)` drift.
   - *Acceptance*: `mcp/tests/fixtures/shots/README.md` exists and contains sections for each fixture and each of items (a)–(e); verifiable by reading the file.

8. **Fixture selection — pragmatic with diversity floor**: Fixture selection targets three archetype slots — (a) healthy bloom-slide profile (target: Shot 170 Choco Coffee Hacienda La Papaya Typica Anaerobic if still in history), (b) pre-bloom-era / decline-profile shot, (c) BT-scale-artifact shot (a shot with weight anomalies — 0g drops, spikes, or unstable-weight flags in the current transformer output). Selection rules:
   - Only shots already in device history or the private data repo are eligible. No hardware sessions (no running old profiles, no inducing BT artifacts).
   - If archetype (a) Shot 170 is not available, substitute with the nearest-available dialed-in bloom-slide shot and document the substitution.
   - If archetype (c) BT-scale-artifact is not available, **omit** it rather than substitute — a healthy shot labeled as (c) is an anti-fixture with zero regression-detection value for the weight-handling bug class. Select a third fixture from a different dimension (e.g., a different profile family or coffee origin not already covered by (a) and (b)) and label it explicitly in the README as a "diverse alternate" rather than as archetype (c).
   - Archetype (b) may also be substituted or omitted under the same rules.
   - **Diversity floor**: the three fixtures must span at least 2 distinct profile types (e.g., bloom-slide + decline, not three bloom-slides) AND at least 2 distinct coffee origins (or the same origin with meaningfully different dose/grind). Three shots from the same profile + same coffee + similar grind do not satisfy R8, even if the archetype-slot labels differ.
   - Minimum count is ≥ 3 regardless.
   - **Private-repo archive (eviction insurance)**: each committed `.slog` is also copied to `{private-data-repo}/mcp-data/shot-archive/<shot_id>.slog` at implementation time, where `{private-data-repo}` is read from `.data-repo-path` at the project root. The main-repo copy remains authoritative for the test harness; the archive is pure redundancy for future investigations (e.g., if a downstream ticket needs to re-derive something from raw bytes after the device has evicted the shot). The archive copy is committed and pushed to the private data repo via the auto-commit policy in CLAUDE.md.
   - *Acceptance*: (a) the README's per-fixture rationale section names the intended archetype slot (or "diverse alternate"), the actual shot chosen, a one-sentence substitution/omission rationale if different from the ticket's named candidate, and a diversity summary sentence confirming the profile-type and origin distribution; (b) for every `.slog` in `mcp/tests/fixtures/shots/`, a byte-identical copy exists at `{private-data-repo}/mcp-data/shot-archive/<shot_id>.slog` (verifiable via `diff`); skip (b) only if `.data-repo-path` is absent at the project root, in which case the implementer notes the skip in the README.

9. **CI follow-up note in PR description**: Because no CI config exists at the repo root (`.github/workflows/` absent; confirmed), the ticket does not wire the test into any pipeline. The PR description includes a short "Follow-up" note recommending that `mcp/tests/test_shot_regression.py` and `mcp/tests/test_shot_fixture_walker.py` be gated once CI is added. No cross-ticket edit to `backlog/013-*.md` or another lifecycle artifact is required.
   - *Acceptance*: session-dependent: the PR description carries the follow-up note. No grep-able artifact file required.

## Non-Requirements

- **No new dev dependencies.** The harness is stdlib + existing pytest stack only (`pytest`, `pytest-asyncio`, `pytest-cov`). The deep-equality walker is hand-rolled per Requirement 5 — not a wrapper around `recursive-diff`, `DeepDiff`, `syrupy`, `pytest-regressions`, or `numpy.testing`. Rationale: the walker's contract is narrow and stable (exact-equality under pre-rounding invariant), error-message format is load-bearing for golden-diff review, and the 50–80 LOC implementation + tests is a one-time cost vs ongoing third-party dep maintenance.
- **No JS-reference sidecars.** `<shot_id>.reference-js.json` files are owned by ticket 018 (which has its own "Implementation prerequisite: capture reference JS output" section). 016 does not build or use the JS-capture mechanism.
- **No `manage_shot_notes` testing.** Sidecar note round-trip is ticket 014's scope.
- **No CI pipeline creation.** The ticket flags this as a follow-up in the PR description but does not create `.github/workflows/`, a `Makefile`, `tox.ini`, pre-commit config, or git hooks.
- **No snapshot library or `--snapshot-update` flag** (e.g., `syrupy`, `pytest-regressions`). Refresh is always explicit via the CLI module, never triggered by a pytest flag.
- **No replacement of existing synthetic-input unit tests.** `test_parsers_shot.py` and `test_transformers_shot.py` continue to cover in-memory `struct.pack`-built inputs; this harness adds real-data regression coverage alongside them.
- **No hardware sessions.** The ticket does not instruct the user to pull new shots, run old profiles, or induce BT-scale artifacts to satisfy an archetype.
- **No fixture eviction policy in this ticket.** Once a fixture is checked in, it stays until intentionally replaced; the ticket does not design a rotation or expiry mechanism. (Whether to backup `.slog` bytes to the private data repo as eviction insurance is an Open Decision — see below.)
- **No attempt to preserve pre-upgrade (1.7.3) shots for ticket 021.** User-reported finding (2026-04-19): the Gaggimate firmware wipes shot history on firmware upgrade, so no pre-1.8.0 shots survive on this device. 021's BLE-precision drift sub-question is therefore definitionally unanswerable from device history; 021 will have to scope around that constraint in its own ticket (e.g., by synthesizing the drift investigation from known-precision inputs, or by documenting the sub-question as closed-unanswerable).
- **No float tolerance in the regression test.** Exact equality only. See Requirement 4 rationale.

## Edge Cases

- **Fixture `.slog` missing at test time**: `test_shot_regression.py` parametrizes over files found at collection time. A missing `.slog` is invisible (no test emitted). This is acceptable because the README is the source of truth for expected fixtures; if a file gets deleted, the README comparison surfaces it during review.
- **Golden `.json` missing for a present `.slog`**: the pytest fails at file-load time with a message pointing to the refresh CLI default mode. Example: `Missing golden: mcp/tests/fixtures/shots/170.golden.json — regenerate via 'python -m gaggimate_mcp.tools.refresh_fixtures 170'.`
- **Transformer raises during fixture run**: pytest surfaces the exception directly — no `try`/`except` that swallows the error. Test fails with the exception stack, identifying the fixture.
- **Float or field drift detected**: the custom helper raises `AssertionError` with up to 10 field-path mismatches collected before raising, giving the reviewer a batched view of whether the drift is localized (one field) or systemic (a schema shift).
- **Categorical field drift** (e.g., `phase.name` changes from `"bloom"` to `"pre-infusion"`): exact-equality check fails with a field-path message.
- **New field added to `TransformedShot` but golden not refreshed**: walker reports `extra key in actual: <path>` or `missing key in expected: <path>` with the full path.
- **Committed `.slog` valid but evicted from device**: default-mode refresh succeeds (no device needed). Fetch-mode refresh on the same `shot_id` returns a 404; the script exits non-zero and reminds the user that default mode still works off the committed bytes.
- **Fetch mode without device connectivity**: HTTP client raises a connection error; the script exits non-zero with the underlying error surfaced.
- **`None` / `null` round-trip invariant**: `compute_compliance_metrics` returns `None` for RMSE fields when fewer than 3 samples carry targets; these serialize as JSON `null`. The walker treats `None` as a first-class value under exact equality (`actual is None and expected is None`). A future refactor that replaces `None`-valued keys with `dict.pop` or `{k: v for k, v in ... if v is not None}` would make the key missing instead of null — the walker's extra/missing-key message surfaces the change unambiguously, protecting the contract.
- **Partial refresh in a downstream PR** (e.g., 015 refreshes 2 of 3 goldens, forgets the third): the regression test fails on the un-refreshed fixture with either a missing-key (new field not in old golden) or extra-key message. The failure pins the forgotten fixture by path. Review depends on a contributor running `pytest mcp/tests/test_shot_regression.py` before merge; the README's "refresh workflow" section calls this out explicitly.
- **Pre-upgrade (1.7.3) `.slog` does not exist on device**: firmware wipes shot history on upgrade (user-confirmed 2026-04-19). No pre-upgrade fixture can be captured from this machine. README notes this explicitly as context for ticket 021.

## Technical Constraints

- **Python 3.13+** (per `mcp/pyproject.toml:9`). Contributors regenerating goldens should use the same Python minor version that produced the existing goldens (nominally 3.13.x — documented in the README per R7(e)) to avoid cross-version `repr(float)` differences that would break R3 byte-stability on a reviewer's machine even when transformer output is identical.
- **Deterministic transformer today — pre-rounding is load-bearing**: verified in research — no `random`, no `datetime.now()`, no hash-dependent iteration, no threading; all numeric output fields (`TransformedSample`, `ShotSummary`, per-phase aggregates, `ComplianceMetrics`) are pre-rounded at the transformer level (1 d.p. for summary stats, 2 d.p. for RMSE and compliance metrics). Under these conditions, `json.dumps(sort_keys=True, indent=2)` produces byte-stable output and exact `==` equality is both correct and sufficient. The regression test enforces this invariant by design — if a contributor introduces an un-rounded float into the output, the exact-equality check will fail and force a conversation before such floats enter the fixture contract. **Do not add a float tolerance "just in case"**; for 2-dp-rounded fields, any tolerance smaller than 0.01 is a phantom guard (deltas are either 0 or ≥0.01) and a tolerance of 0.01 would hide real regressions.
- **Non-terminating binary float repr (e.g., `0.1`) is safe**: `json.dumps` uses Python's shortest-roundtrip `repr()` which is stable within a Python minor version. Pre-rounding means the values serialized are round-roundtripped decimals like `0.1`, not their binary-artifact forms. No special float encoder needed.
- **`gaggimate_mcp.tools` module convention** (implicit, set by `refresh_fixtures.py`): synchronous `main(argv: list[str]) -> int` entry point invoked via `if __name__ == "__main__": sys.exit(main(sys.argv[1:]))`; argparse for flag parsing (since `--fetch` is needed); errors surfaced via `print(..., file=sys.stderr)` + non-zero exit code (no raised exceptions escape); no logging framework setup needed for CLI tools of this size. Async code (e.g., the existing `http.fetch_shot`) is called via `asyncio.run(...)` inside `main` rather than making `main` itself async.
- **Fixture file size budget**: each `.slog` is ~20–50 KB; with goldens roughly 5–10× larger, total fixture weight is well under 1 MB across 3 shots. No Git LFS needed.
- **Binary fixtures are test infrastructure, not data**: they live in the main repo at `mcp/tests/fixtures/shots/`, not in the private data repo. This diverges from `coffees/` / `grind-map.md` / `user-setup.md` (which are symlinked from the private data repo) because the harness must be runnable on any clone without data-repo configuration. An archive copy also lives at `{private-data-repo}/mcp-data/shot-archive/` per R8 for eviction insurance — but the main-repo copy remains the authoritative source for the test harness.
- **Firmware wipes shot history on upgrade** (user-reported, 2026-04-19): any pre-upgrade (1.7.3) shots the user had are gone. This closes the possibility of capturing a pre/post pair for BLE-precision drift analysis from this device; 021 cannot rely on 016 providing such a pair.
- **Transformer output shape is a TypedDict**, not a Pydantic model. Serialization uses stdlib `json.dumps` directly — no `model_dump_json()` determinism concerns.
- **Device connectivity required for `--fetch` only**: the pytest and default-mode refresh run fully offline; only `refresh_fixtures --fetch` needs `GAGGIMATE_HOST` resolvable.
- **No existing CI**: harness is a local developer verification tool; the developer is the review gate for golden diffs. The README documents this explicitly so future contributors understand the review surface.
