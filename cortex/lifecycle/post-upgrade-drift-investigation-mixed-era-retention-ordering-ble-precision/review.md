  1. **Mid-rebuild read-endpoint consistency hazard** (retention section, lines 393–405): PR #604's async rebuild deletes `/h/index.bin` before replaying, and read endpoints (`req:history:list`, `req:history:get`) are NOT gated during rebuild. A client refresh mid-rebuild will see a partial or empty index. This could affect MCP `list_recent_shots` / `fetch_shot` reliability if the user triggers a device reboot or manual rebuild while a barista-agent session is active.
  2. **SPIFFS logical-vs-physical free-space gap** (retention section, line 343): on SPIFFS (not SD_MMC), `getFreeSpace()` returns a logical figure that can exit "enough space" even when the filesystem is functionally full due to fragmentation. This could cause eviction not to trigger when needed on SPIFFS-backed boards.
- Per the spec's Non-Requirement, not propagating these to CLAUDE.md is correct spike behavior — drift detection is "none" because the spike intentionally records discoveries in-section. If the user later chooses to propagate either trap (the mid-rebuild hazard is arguably the more agent-operationally-relevant of the two), that's a user-initiated follow-up outside this spike's scope.

**Update needed**: None (within scope of this spike). User-initiated follow-up to propagate the two in-section traps to CLAUDE.md's "Firmware 1.8.0 semantic traps" block is an option to consider but is outside spike authority per Non-Requirement.
