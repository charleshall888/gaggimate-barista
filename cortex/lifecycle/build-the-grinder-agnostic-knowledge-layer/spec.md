# Specification: Build the grinder-agnostic knowledge layer (DF64V + notation + de-Sette)

## Problem Statement

The repo's grinder knowledge is hardcoded to the Baratza Sette 270: the only grinder reference documents its stepped macro+micro dial, grind settings are written in Sette codes that survive neither a re-zero nor a burr swap, and the shared extraction files teach using the Sette as *the* worked example in Sette-specific "macro steps." A barista on the DF64V (or any other grinder) gets adjustment instructions that don't map to their dial. This ticket builds the **knowledge-content layer** of the grinder-agnostic migration — a per-grinder operating reference for the DF64V with factory-fitted SSP Cast Lab Sweet V3 Red Speed *espresso* burrs, a reusable per-grinder template, a grinder-neutral grind-logging notation, and shared extraction knowledge re-keyed to grinder-relative language that defers per-grinder specifics to whichever grinder the config names. After 025 the *content* is grinder-agnostic and forkable; the *runtime wiring* that makes a skill actually load the DF64V reference and resolve the active grinder is delivered by siblings 026 (live grind-map + `user-setup.md` Grinder field) and 027 (skills). Scope is the knowledge content only; the live grind-map switch (026), the skills refactor (027), and physical commissioning + profile re-dial (028) are separate tickets.

## Phases

- **Phase 1: Grinder-agnostic foundation** — establish the notation contract, the DF64V two-file reference, the per-grinder template, and the knowledge-index entry (the ticket's "notation + DF64V + template first" order).
- **Phase 2: De-Sette the shared knowledge** — re-key the shared extraction-knowledge files and the example grind map from Sette-specific macro-step language to grinder-neutral language that cross-links the Phase-1 foundation.

## Edge Cases

- **Pre-migration Sette grind-map rows are dead-coordinate data.** `_NOTATION.md` (R1f) must state that values logged in a prior grinder's units (e.g. Sette `13D`) do not translate and are not carry-forward — consumed later by 026/027.
- **A re-zero or burr swap mid-life invalidates earlier "chirp + N marks" values.** R1(c)/(d) require a concrete epoch-binding + row-superseding convention so a value is never ambiguous about which zero it belongs to; the principle alone is insufficient.
- **Seasoning drift during the user's current break-in.** Early DF64V values re-mean themselves as the zero drifts coarser through ~5–10 kg; the reference and notation must flag this so the user doesn't over-trust week-1 settings.
- **A forker has a conical grinder, not a flat one.** The de-Setted shared knowledge must not assume a flat burr; the body/clarity *cup-character* tendency defers to whichever grinder the Grinder field names (its hedged burr-character note).
- **Sibling-burr fact contamination.** A statement true of SSP Multipurpose (stall-elimination) or generic SSP (2–3 kg seasoning) but not the Cast line must not appear unqualified in `DF64V.md`/`DF64V_REFERENCE.md` (enforced by R14).
- **Grep passes but content is wrong.** A DF64V file can pass every string-presence grep while still asserting a wrong-variant fact; R14's content checklist is the gate that catches this, not the R2/R3 greps.

## Technical Constraints

- **CLAUDE.md is the binding governance** (the formal `cortex/requirements/project.md` is an unconfigured stub). The de-Setted knowledge must NOT contradict the Core Rules — especially **"Sour AND bitter = channeling → fix puck prep, NOT grind"** (grinder-relative step advice is for under/over-extraction only, never a channeling fix) — nor introduce absolute numbers competing with the Temperature-by-Roast (`CLAUDE.md:138–145`) and Pressure-by-Processing (`CLAUDE.md:147–154`) tables. The safe relative phrasing is "go finer/coarser by a small step." "chirp + N marks" is a logging *coordinate*, never an adjustment-step unit.
- **Authoritative hardware source** is `cortex/research/df64v-ssp-migration/research.md` (Q2 recalibration). The seven "wrong-if-stated-baldly" facts (enumerated in R14) are binding hedging constraints on `DF64V.md`/`DF64V_REFERENCE.md`, verified by R14's content checklist rather than by greps.
- **Internal order** (ticket Edge): Phase 1 (notation + DF64V + template) must land before Phase 2 cross-links them; the de-Setted files use grinder-neutral indirection rather than literal new paths so a later path change doesn't strand them.
- **Handoff to ticket 027** (informational; 025 does not edit these): the skill lines still naming the Sette are `new-coffee/SKILL.md:58,66`; `new-coffee/references/SELF_CHECK.md:14,133`; `consult/SKILL.md:28,77` (keyword router + deep-reference route); `feedback/SKILL.md:29,136` (the last includes an invalid `"10M"` Sette example — Sette micro letters are A–I — for 027 to correct).
