## Web Research

Hardware facts verified/recalibrated against current independent sources (Tom's Grinder Lab, Coffee Chronicler, Brew Coffee Home, Home-Barista) vs retailer/marketing. **Seven statements that would be WRONG if stated baldly in `DF64V.md`:**

1. **Stall cause** — independent sources (Coffee Chronicler, Home-Barista) attribute the low-RPM stall largely to a **control-board protection mechanism**, much of it a **fixed pre-production-board defect** (~20 early 110V units; serial-check + replacement board exist) — NOT the "DC motor lacks low-RPM torque" line the MiiCoffee *retailer* blog gives. Write as "largely a fixed early-board issue + an edge case at low RPM with dense light roast fed all at once," not a motor flaw.
2. **Espresso RPM** — independent testers converge on **~1000–1200** (Tom's 1200, Brew Coffee Home 1100). **1400 is MiiCoffee's higher-body retailer preference, not a floor.** Default ~1000–1200; offer 1400 as an optional more-body lever (hedged — see #6).
3. **SSP-MP-eliminates-stall** — reported for the **Multipurpose** line ONLY (Coffee Chronicler). Transfer to the higher-fines **Cast** line is **unconfirmed**; Cast makes *more* fines. Stating "SSP eliminates the stall" would be wrong for this user's Cast burr.
4. **Seasoning** — generic-SSP guidance is 2–3 kg, but the on-point Home-Barista "DF64v + SSP LS Cast V3" thread reports **~7–9 kg** to settle. Use "**~2–3 kg before you trust settings, real settling out to ~5–10 kg**" (spans both). "NOT rice — coffee only" confirmed.
5. **Microns-per-mark** — **no credible figure exists** for the DF64V stepless collar, and a micron number is **burr-gap displacement, not particle size** (Pro Coffee Gear / Mahlkönig). Ticket non-goal; decline to prescribe and say why.
6. **"Flats tolerate higher pressure" / "RPM is a body lever"** — contested theory (Prima: "a hot topic of debate") and partly **contradicted** by the one rigorous measurement (R. McKeon Aloe: higher RPM shifted the distribution *coarser* / *fewer* fines — opposite of the vendor "high RPM = more fines = more body" story). Hoffmann's blind testing found **no clean burr-shape → body/clarity correlation**. Hedge hard; present as vendor-framed/unproven.
7. **"Red Speed adds body"** — vendor claim; Grind Logic itself says coating effect is "secondary and grinder-dependent." Present as plausible/vendor-reported, not measured.

**Corroborated (safe to state)**: chirp/zero dialing grammar (run motor, creep finer to first chirp = zero reference, back off; re-zero after clean/burr-swap); retention **~0.1 g with mandatory bellows**; 58 mm dosing cup; standard 64 mm flats / SSP drop-in (Fiorenzato & Mazzer excepted); espresso start window **~10–20 marks from zero**; static/clumping → RDT; V3 = espresso re-cut of filter V2 (~15% more cutting edges), Red Speed = TiAlCN (more friction) vs Silver Knight = DLC (cleaner). Espresso Outlet (retailer) dis-recommends Cast Lab Sweet for espresso as "difficult to dial in" — surface the dial-in-fiddliness tension rather than ignore it. **No quantitative particle-size data exists for these burrs** (confirmed across all sources).

## Adversarial Review

1. **Live grind-map is a data discontinuity, not a format re-key.** The live `grind-map.md` (private-repo symlink) holds **12 real Sette-keyed rows** (`13D`, `12E`…). `13D` has **no conversion** to "chirp + N marks" on a DF64V. 025's notation contract must explicitly state that pre-migration Sette rows are **dead-coordinate reference data** (a different grinder's coordinate system), not values 026 carries forward or 027's freshness math operates on. (The live map is 026's to handle, but 025 defines the contract that says so.)
2. **The notation guidance isn't currently airtight.** `feedback/SKILL.md:136` gives an **invalid** Sette example `"10M"` (micro letters are A–I only) — evidence that a loose format string gets reproduced as garbage. 025's notation definition must be **tight** (bounds + zero-reference rule), or 027 inherits the looseness.
3. **HIGHEST CORRECTNESS RISK — the conical-vs-flat lesson is itself web-contested, and the SSP Cast is a *higher-fines* flat.** The existing teaching asserts a clean conical→body / flat→clarity dichotomy; Agent 2 found Hoffmann's null result and McKeon Aloe's contradicting RPM-fines measurement. Dropping the user's actual new burr into the "low-fines flat → fewer fines → more clarity" cell is **arguably factually wrong for this burr** (SSP Cast Red Speed is the *higher-fines* SSP option) and canonizes an oversold claim the user would then dial against. **Mitigation: soften the table to contested *tendencies*, not deterministic law; do not add SSP Cast as an authoritative clarity exemplar.**
4. **Skills are downstream consumers of 025's contract and break if knowledge de-Settes without skill rewiring (027).** 025 must (a) use a **grinder-neutral indirection** in cross-links ("the active grinder's reference, per the Grinder field"), never a literal `SETTE_270.md` path, and (b) **emit a handoff list** of every skill line still naming Sette (`new-coffee/SKILL.md:58,66`; `new-coffee/references/SELF_CHECK.md:14,133`; `consult/SKILL.md:28,77`; `feedback/SKILL.md:29,136`) for 027.
5. **"chirp + N marks" is not a stable record without epoch semantics.** Chirp moves on burr-swap/re-zero and the zero **drifts coarser through the exact 5–10 kg seasoning window the user is in now** — so the same notation re-means itself over weeks, producing false-confidence reproductions. The contract must specify: (a) a **zero-reference epoch** (a re-zero invalidates prior rows — mark them, don't carry forward); (b) the value is an **operator-relative coordinate, explicitly NOT a micron/particle-size claim**; (c) a **seasoning-state caveat**.
6. **Correct-hardware residual mislead: don't inherit a sibling-burr's measured behavior.** Even with the right SKU named, importing a fact true of *MP* (stall-elimination) or *generic SSP* (2–3 kg seasoning) misleads for *this Cast burr*. **Every quantitative claim in `DF64V.md` needs a "this Cast burr / this line" qualifier or should be omitted.**
7. **Internal ordering can strand cross-links.** If de-Setted files (step 2) link to a notation/grinder file whose final path (Decision A) shipped under a name that later changes, they point at nothing. Mitigation: **settle final paths before writing any cross-link**, and prefer grinder-neutral indirection over literal new paths.
8. **An "optional `_REFERENCE`" template is an under-specified scaffold.** Forkers will guess the operate/maintain boundary differently. The template should **encode the seam as explicit headed sections with "put X here / Y in the reference" instructions**, not leave it to judgment.
9. **`DF64V_REFERENCE.md` not on any discovery surface = orphaned.** "The `_REFERENCE` files aren't in CLAUDE.md so mine needn't be" is a **false analogy** — they're reachable via the `/consult` router (`consult/SKILL.md:77`). A reference in neither CLAUDE.md nor the router would never load. If 025 creates it, put it on a discovery surface or explicitly hand the wiring to 027.
10. **The ~0.5 g vs ~1 g Sette-retention inconsistency is NOT a Sette-correctness question to adjudicate (scope creep).** Both lines should be **re-keyed to the active grinder's retention (~0.1 g w/ bellows for the DF64V) or have the Sette gram figure genericized out** — at which point the contradiction **dissolves as a side effect**. Flag in handoff; don't "reconcile the right Sette number."
